Educational analytics · synthetic research

Learning App Analytics

A reproducible lab that asks whether synthetic practice-session evidence can support cautious next-action classification without turning a model score into an automatic learner decision.

Evidence boundary: every row and label is synthetic. The project demonstrates workflow and evaluation judgment; it does not prove what any real learner should do next.

01 · Problem

What should a learning product review after a practice interaction?

The model classifies a synthetic interaction as advance, review, or hint_needed. The practical question is not merely which classifier scores highest. It is whether the workflow exposes enough uncertainty and context for a tutor or product team to challenge the output.

02 · Data and provenance

The dataset is controlled, synthetic, and auditable.

One row represents one synthetic practice-problem interaction. Features include topic, subtopic, difficulty, attempts, time spent, correctness, hint use, prior and recent accuracy, streak length, practice recency, confidence self-report, and fatigue.

Generator-only latent fields are retained for audit but excluded from model feature lists. This makes it possible to inspect how labels were constructed without allowing the model to read the hidden variables directly.

03 · Workflow

The execution path produces both models and review artifacts.

  • Generate and validate the synthetic dataset.
  • Build base and engineered feature sets.
  • Train a majority baseline, logistic regression, random forest, engineered variants, and a calibrated random forest.
  • Evaluate a transparent rule policy on the same grouped test frame.
  • Export class metrics, confusion matrices, calibration plots, slices, confidently wrong examples, policy outputs, model cards, and final reports.

04 · Evaluation design

Repeated learners require more than a random row split.

The primary experiment holds out students as groups. A separate robustness script compares random-row, grouped-student, and temporal session-order proxy splits. That comparison is important because an apparently strong result can weaken when the evaluation better resembles unseen learners or later sessions.

Calibration is included because an overconfident next-action probability could encourage overly aggressive intervention. The modernization review also flags inner calibration-fold grouping as a remaining technical review item until branch validation is complete.

05 · Current evidence

The project retains simple baselines instead of hiding them.

EvidenceWhy it matters
Majority, linear, tree, and calibrated modelsShows whether added complexity earns its place.
Transparent rule policyAnswers “why not use inspectable rules?” on the same test frame.
Grouped and temporal proxy comparisonsTests whether the story survives stricter partitions.
Calibration, class, slice, and error reportsMoves review beyond one global metric.

Exact numeric values are regenerated on the modernization review branch. This public page avoids treating a committed synthetic score as a permanent benchmark.

06 · Decision policy

A classifier output is not a learner-facing action.

The policy layer can route low-confidence, fatigue-heavy, missing-context, or confidence/performance-conflict cases to diagnostic questioning, abstention, or human review rather than automatically advancing or intervening.

07 · Limitations

The strongest limitation is also the central truth of the project.

  • The model learns generator assumptions, not observed learning mechanisms.
  • No real learner benefit, product lift, fairness, or causal impact is demonstrated.
  • A temporal proxy is not a substitute for governed longitudinal product data.
  • The source repository is private, so public technical inspection is limited until a release decision is made.
  • The project is not deployment-ready.
